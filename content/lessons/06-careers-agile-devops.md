## Where we're headed

This lesson zooms out from code to career: what the job market actually looks like, what "full stack" really includes, and the team practices — Agile and DevOps — you'll encounter on almost any professional team.

## Concepts & Terminology

The U.S. Bureau of Labor Statistics groups full stack developers under its broader "web developers and digital designers" category, and projects that employment in that category will grow about 7 percent from 2024 to 2034 — faster than the average for all occupations — with roughly 14,500 openings projected each year over the decade (source: [BLS Occupational Outlook Handbook](https://www.bls.gov/ooh/computer-and-information-technology/web-developers.htm)). That's a healthy, durable outlook — and it holds even as AI tools change *how* developers work day to day, which we'll return to below.

Full stack work typically spans several layers:

- **Front-end**: HTML, CSS, JavaScript, accessibility, design, and front-end frameworks.
- **Middle tier**: server-side languages like Node.js, Python, or Java, and their frameworks.
- **Data**: SQL databases, and increasingly NoSQL/document databases for less structured data.
- **Supporting technology**: npm, Git and GitHub, the command line, JSON and APIs.
- **Process and teamwork**: Agile, DevOps, project management, requirements gathering, meeting facilitation.

No developer is expected to master all of it at once — most build deep expertise in one or two layers while staying conversant in the rest.

**Agile** is a development methodology built around adapting to changing needs rather than resisting them. **DevOps** is a broader culture of collaboration between everyone involved in building and running software — developers, operations, QA — so that releasing new code is a routine, low-drama event rather than a rare, high-stakes one. The two ideas complement each other: Agile shapes *how a team decides what to build next*; DevOps shapes *how that work reliably reaches users*.

A **sprint** is a short, fixed period (often one to two weeks) in which a team plans work, executes it, and checks in daily via a brief **standup** meeting. Even solo developers often borrow this rhythm, because a small, time-boxed goal is easier to finish than an open-ended one.

## Technology

Two developments worth knowing about as you plan a career in this field:

- **AI-assisted coding** (tools like GitHub Copilot and Claude Code) has become a standard part of the professional toolkit. It doesn't replace understanding the fundamentals in this course — if anything, it raises the value of being able to read, evaluate, and debug code an AI suggested, rather than just typing faster.
- **Modern hosting** has gotten dramatically simpler and cheaper. Where an older course might have you provisioning a full server, most new projects today deploy to platforms like Cloudflare Pages, Netlify, or Vercel, often for free at small scale.

## Soft Skills

- **Job search tools** worth knowing: LinkedIn and Indeed remain standard for search, but a public GitHub profile with a few real, documented projects is often what actually gets a resume a second look.
- **Bootcamps and community programs** remain a legitimate path into the field alongside a traditional degree — organizations like Girls Who Code run programs specifically aimed at increasing representation in tech.
- In interviews and on the job, being able to explain *why* you built something a certain way is just as valuable as the code itself.

## Try It

Search "junior full stack developer" or "junior web developer" on a job board and read three postings closely. Note which of the technologies from this course's toolkit list show up most often.

## Recap

- Web/full-stack development has a positive, faster-than-average job growth outlook through the next decade.
- Full stack work spans front-end, middle tier, data, and supporting tools — depth in one or two areas is normal.
- Agile shapes what a team builds next; DevOps shapes how that work reaches users reliably.
- AI coding tools are now standard, which makes fundamentals-level understanding more valuable, not less.
